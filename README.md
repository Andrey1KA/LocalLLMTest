# Интеллектуальный менеджер задач

Небольшое приложение, в котором список задач и языковая модель работают в одном процессе. Модель предлагает категорию, разбивает задачу на подзадачи, рекомендует приоритет и собирает сводку нагрузки. Ответ проверяется схемой до того, как попадает в интерфейс.

Один и тот же код ходит либо в облачный API, либо в локальную модель с совместимым адресом. Для локального прогона использовались Ollama и `qwen3:30b` на NVIDIA L4 24 ГБ. Страницы приложения при этом оставались на компьютере разработчика, модель — на сервере.

## Что умеет

Задачи: создание, просмотр, изменение и удаление с подтверждением. Поля: название, описание, приоритет, статус, срок, категория.

Список на сервере: фильтр по статусу и приоритету, поиск по названию и описанию, диапазон сроков, только просроченные, сортировка и постраничная выдача.

Модель, четыре сценария:

- категория по названию и описанию;
- декомпозиция, строки можно поправить, затем создать отдельной задачей каждую;
- приоритет с учётом срока;
- сводка нагрузки потоком.

Без ключа и без локального адреса включается демо-режим: интерфейс отвечает стабильными заглушками и к модели не обращается. Ответы модели в реальном режиме разбираются как JSON и проверяются Zod. Одинаковые запросы кэшируются, параллельные склеиваются, число вызовов с одного клиента ограничено.

## Локальный прогон 25 октября 2026

Модель `qwen3:30b` (Q4_K_M, файл 18 ГБ), Ollama 0.40.11, арендованный сервер с NVIDIA L4. В видеопамяти во время ответа было занято 18244 МиБ из 23034 МиБ. На одном русском вопросе, когда веса уже были в памяти, скорость генерации составила 95,7 токена в секунду. Контекст запроса ограничен 4096, чтобы окно модели поместилось в 24 ГБ.

В интерфейсе на задаче про брак на линии проверены все четыре сценария: категория «Контроль качества», три подзадачи, приоритет «Высокий» и сводка с разбивкой по приоритетам. Рядом проверены поиск, фильтры, редактирование, страница задачи и удаление.

## Запуск

Нужен Node.js 20+.

```text
npm install
copy .env.example .env
npx prisma migrate deploy
npm run dev
```

Приложение открывается на [http://localhost:3000](http://localhost:3000) и переходит к списку задач. Фронтенд и API — один процесс Next.js.

Локальная модель: поднять Ollama, скачать тег из `ollama list`, в `.env` указать адрес и имя модели. Если Ollama на другой машине, с этого компьютера достаточно туннеля `ssh -L 11434:127.0.0.1:11434 user@server`, порт наружу не открывается. Ключ облака при этом можно не задавать.

```text
OPENAI_BASE_URL=http://127.0.0.1:11434/v1
OPENAI_MODEL=qwen3:30b
LLM_NUM_CTX=4096
```

Облако: пустой `OPENAI_BASE_URL`, заполненные `OPENAI_API_KEY` и `OPENAI_MODEL`.

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | SQLite, например `file:./dev.db` |
| `OPENAI_API_KEY` | Ключ облака. Пусто и без адреса — демо. Для Ollama можно оставить пустым |
| `OPENAI_BASE_URL` | Совместимый адрес. Для Ollama `http://127.0.0.1:11434/v1`. Пусто — официальный OpenAI |
| `OPENAI_MODEL` | Имя модели. Локально — тег из `ollama list` |
| `LLM_NUM_CTX` | Контекст локальной модели. Пусто — 4096. В облачный запрос не отправляется |
| `LLM_CACHE_TTL_MS` | Срок кэша ответов, мс. `0` выключает кэш |
| `LLM_RATE_LIMIT_MAX` | Сколько запросов к модели с одного клиента за окно. `0` выключает лимит |
| `LLM_RATE_LIMIT_WINDOW_MS` | Длина окна лимита, мс |
| `LLM_LOG_USAGE` | `1` — печатать число токенов в stdout |

Файл `.env` в репозиторий не входит.

Тесты: `npm run test:run`. Сквозные сценарии: `npm run test:e2e` после `npm run test:e2e:install`.

## Как устроено

Запрос страницы идёт в Route Handler `src/app/api/v1`, затем в сервис и репозиторий Prisma. База — SQLite. Вызов модели собран в `src/lib/services/llmService.ts`: клиент OpenAI SDK получает `baseURL`, остальной код от адреса не зависит. Для локальной модели в запрос добавляются контекст и отключение режима рассуждения, чтобы ответ оставался JSON.

Интерфейс: React, Ant Design, TanStack Query. Состояние доски — `src/state/tasksBoard`.

Стек: Next.js 14, React 18, TypeScript, Ant Design 5, TanStack Query, Prisma, SQLite, Zod, OpenAI SDK, Vitest, Playwright.

## Ограничения

Общая база без учётных записей. Подзадачи создаются отдельными записями, без ссылки на родителя. Поиск SQLite может различать регистр. Кэш и лимит запросов живут в памяти одного процесса. Сводку пишет модель, готовые агрегаты заранее не считаются.
